# Windows 自动更新修复报告

检查日期：2026 年 10 月 31 日。范围：Windows 更新下载、校验、安装进程交接、重启、编辑状态保护及发布包。对应用户反馈：下载进度停在约 93%，随后 Windows 提示无法找到文件。

## 结论与根因

原实现把安装包路径拼进 `cmd.exe /C` 和 `START` 命令。Rust 的 Windows 参数编码与 cmd 的命令解析规则不同，路径经过两层解释，存在空格、中文和特殊符号时可以启动失败。自有无害程序实测：旧启动方式返回 1 且未执行安装器，同一路径直接作为进程参数则正常。测试环境显示的具体错误文字不同，不能据此声称已逐字复现用户截图。

进度停在 93% 还有独立的显示原因：下载进度是采样事件，下载完成后仍需获取校验清单并计算摘要，旧界面没有显示该阶段。93% 本身不足以判断网络下载失败。

原流程还使用固定延时猜测主程序已关闭，无论安装成功与否都继续重启；前端存在两套自动安装计时器，可能重复发起安装。上述问题均已纳入修复。

## 修改内容

| 范围 | 修改后的行为 |
| --- | --- |
| Windows 启动链 | 使用独立 helper 和 Windows 进程 API，安装包路径作为参数传递；等待真实父进程退出，再等待安装进程结束并判断退出码。 |
| 安装可信度 | 保留官方 SHA-256 清单校验；helper、交接数据及安装包均校验，安装期间禁止写入、删除或替换已锁定的包。 |
| 安装结果 | MSI 仅接受规定的成功码；失败保留日志并明确报错，不重启冒充成功。正常保留 Windows 管理员授权流程。 |
| 下载状态 | 明确显示校验阶段；网络及清单读取可取消、有超时和大小限制，取消后不会再进入正常完成分支。 |
| 并发与取消 | 共享唯一下载、安装任务及自动安装计时器；取消自动安装后不被另一计时器再次触发。 |
| 版本和架构 | 从真实 GitHub Release 选择资产；不凭主分支版本号构造不存在的链接；x64 不选择 ARM64 包。 |
| 编辑内容保护 | 输入法组合期间自动更新延期，手动安装等待组合结束；未保存内容或会话持久化失败时拒绝安装，准备完成后冻结编辑交互。 |
| 便携版安装后重启 | 在持锁的已验证 MSI 内读取 ProductCode 和主程序 ComponentGuid，安装成功后查询实际安装路径；定位失败时明确报错，不回退重启旧便携副本。 |
| 快速收集草稿 | 可见或正在创建的快速收集窗口会阻止安装；安装预约期间拒绝全局快捷键打开窗口，失败释放预约。隐藏驻留窗口不阻塞。 |
| 便携包 | 补齐图标和英文拼写词典；只捆绑对应架构、本次构建的 MCP 程序。 |

Windows Installer API 从系统目录按需加载，资源句柄有明确生命周期；不修改注册表，不绕过管理员授权。快速收集创建与安装预检通过 UI 队列和无阻塞预约协调，覆盖窗口创建期间的重入情况。

## 安装说明与验收边界

本次按用户要求替换 v1.0.13 的 Windows 安装包和便携包。已经安装 v1.0.13 的客户端不会将同版本替换识别为更高版本，因此需要重新下载修复包并覆盖安装一次。旧版本启动器自身的错误也需要通过这次手动安装修复。

进程测试不等同于在所有 Windows 环境完成实际安装。管理员授权、Windows Installer 服务和第三方软件干预，需要在用户安装时实际确认；本次保留安装日志供失败时定位。用户自行安装，未代为关闭或替换其正在运行的应用。
